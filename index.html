Setup Guide
One-time setup to connect Gmail or Zoho Mail with real OAuth — no passwords ever
Why OAuth and not a password? With OAuth, you log in directly through your provider's own screen — Sytesurge never sees your password. The provider gives the app a temporary access token instead. It's the same way "Sign in with Google" works on any website. Your credentials stay entirely with them.

Sending from info@sytesurge.com? That mailbox lives on Zoho Mail, not Gmail — pick Zoho Mail in the "SEND VIA" dropdown up top and use the Zoho Mail Setup card below, not the Google one. Gmail only works if you're actually sending from a real Gmail/Google Workspace inbox.
1
Host on GitHub Pages
The dashboard must be at a fixed URL so Google knows where to redirect after login.

1. Create a free account at github.com
2. Click New repository → name it sytesurge
3. Upload this HTML file as index.html
4. Go to repo Settings → Pages → set Source to main branch
5. Your URL will be:
https://YOURNAME.github.io/sytesurge

✅ Open that URL in your browser — use it from now on instead of this Claude window.
2
Create Google OAuth App
1. Go to console.cloud.google.com
2. Create a new project (e.g. "Sytesurge")
3. Go to APIs & Services → Enable APIs
   → Enable Gmail API
4. Go to OAuth consent screen
   → External → fill in App Name
   → Add your Gmail as test user
5. Go to Credentials → Create Credentials → OAuth 2.0 Client ID
   → Type: Web Application
6. Under Authorized redirect URIs add:
https://YOURNAME.github.io/sytesurge
7. Copy your Client ID
3
Connect
1. Open the dashboard from your live URL
2. Pick Gmail or Zoho Mail in "SEND VIA" (top bar)
3. Paste that provider's Client ID/Secret below and save
4. Click Connect in the header
5. Provider's login screen appears → sign in as info@sytesurge.com
6. Approve the mail-send permission
7. You're redirected back → header shows ✓ Connected

✅ Done! The token is saved in your browser. You won't need to reconnect unless you clear browser data. Both providers can stay connected at once — the "SEND VIA" dropdown picks which one is active.
Google OAuth Credentials (Gmail only)
✅ Fill in all three fields above → click Save → then click 🔐 Connect Gmail in the header bar.
⚠️ Your Client Secret is stored only in your browser — never sent anywhere except Google's servers.
Loss Estimate Methodology — read before using {{est_loss}}
Not legal advice — this is a methodology explanation, not a substitute for a lawyer. The email's {{est_loss}} figure is a claim about money, and the FTC requires advertisers to have a "reasonable basis" for claims like that. Two changes make this far more defensible than a made-up number:

1. It's now a range, not a fake-precise number. "$4,200–$9,800" reads as an estimate; "$14,624" reads as a computed fact you'd need to prove.
2. The conversion-rate assumption is a real, cited 2026 benchmark — general sites average 2.35% conversion (Contentsquare Digital Experience Benchmark Report, 46B sessions; Ruler Analytics, 110M+ sessions), with a widely-cited "good" range of 2–5%. Urgent-need trades (plumbing, HVAC, electrical) convert far higher — cited local-service benchmarks put genuine emergencies at 12–16% — so the contractor category uses a blended 6–14% range to stay conservative.

The other two inputs — monthly visitors and average customer value — have no reliable universal citation, so instead of hiding a guess inside the formula, they're editable fields below. Set them based on what you actually know about your market (city size, typical local ticket prices). This is normal business judgment, the same way a salesperson estimates a ballpark — it's materially different from Claude/the dashboard asserting a precise "fact" with no basis.

Also change how the email frames it: the default template now says "businesses in your industry can lose {{est_loss}} a year" — a general industry statement — rather than telling a specific business what it is losing. That framing matters: general statements about an industry are on much firmer ground than a specific claim about one company's numbers.
Resend Setup — recommended, free, no logo
This is the recommended sender. Resend's free tier sends 3,000 emails/month (100/day) with no branding or logo on your emails, and needs no credit card. The API key stays on the server (Netlify), never in this page.

1. Sign up at resend.com
2. Go to Domains → Add Domain and enter sytesurge.com
3. Resend shows a set of DNS records (MX + TXT for SPF and DKIM). Add each one in Cloudflare → DNS for sytesurge.com, then click Verify in Resend. Takes a few minutes.
4. Go to API Keys → Create API Key, copy the key (starts with re_).
5. In Netlify → Site settings → Environment variables, add a variable named RESEND_API_KEY with that key as the value. Redeploy the site.
6. Pick Resend in "SEND VIA" at the top. No Connect step needed — it's ready.

The from-address below must be on your verified domain (e.g. info@sytesurge.com or Sytesurge <info@sytesurge.com>). Sending from an unverified domain will be rejected by Resend.

Requires the Netlify function to be deployed: the netlify/functions/resend-send.js file must be in your repo. If your Netlify site is linked to this GitHub repo it deploys automatically on push. You can confirm it's live under your site's Functions tab — you should see resend-send listed.
✅ The API key lives only in Netlify's environment variables — it is never exposed in this page or shipped to any client's browser.
Zoho Mail Setup — for info@sytesurge.com
Use this if you actually send from a Zoho Mail inbox (like info@sytesurge.com) — the Gmail card above won't work for that address.

1. Go to api-console.zoho.com and sign in with the Zoho account that owns the mailbox
2. Click Add Client → choose Server-based Applications
3. Homepage URL: your dashboard's live URL. Authorized Redirect URI: your dashboard's live URL (same value as the "Netlify / Cloudflare URL" field below)
4. Copy the Client ID and Client Secret into the fields below and Save. You do not need to set up "CORS Domains" — this dashboard routes every Zoho request through its own server-side proxy (Netlify Functions), so the browser's CORS restrictions never come into play.
5. Pick Zoho Mail in "SEND VIA" at the top, click Connect, and sign in as info@sytesurge.com

Important — this only works if the site is deployed with its Netlify Functions: if your Netlify site is connected to this GitHub repo, the netlify/functions/ folder deploys automatically on every push. If instead you drag-and-drop deployed a folder to Netlify, you'll need to reconnect the site to this GitHub repo (Site settings → Build & deploy → Link repository) or re-upload including the netlify/functions/ folder — otherwise the proxy endpoints won't exist and Connect will fail. You can verify they're live in the Netlify dashboard under your site's Functions tab — you should see zoho-token and zoho-mail listed there.
✅ Fill in both fields above → click Save → set "SEND VIA" to Zoho Mail → click 🔐 Connect in the header bar.
⚠️ Your Client Secret is stored only in your browser — never sent anywhere except Zoho's servers.
Business Data — OpenStreetMap (free, no setup)
The scanner pulls live, real business data from OpenStreetMap via the public Overpass API. There is no API key, no billing account, and no cost — nothing to set up. Just enter a location and press Start Scan.

How it finds leads: every OSM business record notes whether it has a website. With “No website only” on (default), you get exactly the businesses missing an online presence — your ideal prospects.

Honest limitations:
  • OSM does not provide star ratings — the Rating column shows “—”. (No fabricated numbers.)
  • Most records have a phone but no public email. Email those that do; contact the rest by phone/contact form. The campaign step auto-skips leads with no email.
  • Coverage is community-maintained — dense in towns, thinner in rural areas. Widen the radius if results are sparse.
  • Attribution: data is © OpenStreetMap contributors, licensed under the ODbL. Keep the credit shown in the scan log if you republish this data.

Why not Google Places? It requires a billing account, charges ~$32 per 1,000 lookups, and its terms prohibit building a lead/marketing list from the data. OpenStreetMap is free and licensed for exactly this use.
